# FilePizza Development Guide (AGENTS.md)

A peer-to-peer file transfer application built with modern web technologies.

## Prerequisites

- [Node.js](https://nodejs.org/) (v24+, the current LTS; also set in `.nvmrc` and `engines`)
- [pnpm](https://pnpm.io/) (preferred package manager)

## Quick Start

```bash
git clone https://github.com/kern/filepizza.git
cd filepizza
pnpm install
pnpm dev
```

## Available Commands

### Development

- `pnpm dev` - Start the Vite development server (http://localhost:3000)
- `pnpm dev:full` - Start with Redis and COTURN for full WebRTC testing

### Building & Testing

- `pnpm build` - Build for production (Nitro server output in `.output/`)
- `pnpm start` - Run the production build (`node .output/server/index.mjs`)
- `pnpm start:peerjs` - Run the optional self-hosted PeerJS signalling server (`bin/peerjs.js`)
- `pnpm test` - Run unit tests with Vitest
- `pnpm test:coverage` - Run unit tests with coverage (100% per-file thresholds are enforced)
- `pnpm test:watch` - Run tests in watch mode
- `pnpm test:e2e` - Run E2E tests with Playwright in Chromium, Firefox and WebKit against the production build (run `pnpm build` first, and `pnpm exec playwright install` once for the browsers). Run one engine with `pnpm test:e2e --project=webkit`.

### Code Quality

- `pnpm lint:check` - Check Oxlint rules across the whole repo (source, tests, configs and scripts)
- `pnpm lint:fix` - Fix Oxlint issues
- `pnpm format` - Format the whole repo with Oxfmt (generated and vendored files are ignored in `.oxfmtrc.json`)
- `pnpm format:check` - Check code formatting
- `pnpm type:check` - TypeScript type checking

### Docker

- `pnpm docker:build` - Build Docker image
- `pnpm docker:up` - Start containers
- `pnpm docker:down` - Stop containers

### CI Pipeline

- `pnpm ci` - Run full CI pipeline (lint, format, type-check, test, build, e2e, docker)

## Tech Stack

- **Framework**: TanStack Start (TanStack Router + Vite + Nitro)
- **UI**: React 19 + Tailwind CSS v4
- **Language**: TypeScript
- **Testing**: Vitest (unit) + Playwright (E2E)
- **WebRTC**: PeerJS
- **State Management**: TanStack Query
- **Themes**: in-house `ThemeProvider` (class-based dark mode); route navigation uses View Transitions
- **Linting/Formatting**: Oxlint + Oxfmt
- **Storage**: Redis (optional)

## Project Structure

```
src/
├── routes/                 # TanStack Router file routes
│   ├── __root.tsx          #   document shell, head/meta, providers
│   ├── index.tsx           #   upload page
│   ├── download.$.tsx      #   download page (splat slug; loads the channel via a server function)
│   ├── reported.tsx        #   "delivery halted" page
│   └── api.*.ts            #   server routes: /api/create, /api/renew, /api/destroy, /api/ice
├── routeTree.gen.ts        # Generated by the router plugin and committed. Don't edit by hand.
├── router.tsx              # Router factory (view transitions, 404 component)
├── components/             # React components (incl. ThemeProvider and WebRTCProvider)
├── hooks/                  # Custom React hooks
├── utils/                  # Utilities (stream-saver, device-info, ordered-chunks, ...)
├── channel.ts              # Channel storage (in-memory or Redis)
├── messages.ts             # Peer protocol messages (zod schemas)
└── types.ts                # TypeScript definitions
public/
├── sw.js, stream.html      # Service worker and iframe used for streaming downloads
bin/peerjs.js               # Optional self-hosted PeerJS server
docs/                       # Protocol documentation
```

## Development Tips

### Using pnpm

This project uses pnpm as the package manager. Benefits include:

- Faster installs and smaller disk usage
- Strict dependency resolution
- Built-in workspace support

Always use `pnpm` instead of `npm` or `yarn`:

```bash
pnpm install package-name
pnpm remove package-name
pnpm update
```

### Code Style

- Oxlint for linting
- Oxfmt for formatting
- Husky + lint-staged for pre-commit hooks
- Prefer TypeScript over JavaScript
- Use kebab-case for files, PascalCase for components

### Routing and Server Code

- Pages are file routes in `src/routes` (`createFileRoute`). The route tree in `src/routeTree.gen.ts` is regenerated by `pnpm dev` and `pnpm build` and is committed so `pnpm type:check` works on a clean checkout.
- API endpoints are server routes: `createFileRoute('/api/...')({ server: { handlers: { POST } } })`. Handlers take `{ request }` and return a standard `Response`.
- Server-only logic called from a page goes in a `createServerFn` (see `download.$.tsx`) so it stays out of the client bundle.
- The package is ESM (`"type": "module"`). Browser-only code must not run at module load, since routes are also rendered on the server.
- `react-qr-code` is a CommonJS package, so import it by name (`import { QRCode } from 'react-qr-code'`); its default export isn't unwrapped by the production bundle.

### Testing Strategy

- Unit tests for components and utilities (`tests/unit/`)
- E2E tests for critical user flows (`tests/e2e/`), run in every browser engine. `errors.test.ts` covers failure cases (WebRTC unavailable, signalling down, disconnects, wrong password), `sharing.test.ts` covers short and long links and several downloaders, and `firefox.test.ts`, `webkit.test.ts` and `firefox-no-webrtc.test.ts` cover engine-specific behaviour (each runs only in its own project, `firefox-specific`, `webkit-specific` and `firefox-no-webrtc`)
- Test files follow `*.test.ts[x]` naming convention
- Unit coverage must stay at 100% per file (`pnpm test:coverage`)
- E2E tests don't use any public service: `playwright.config.ts` starts `bin/peerjs.js` (port 9000) and the built app with `PEERJS_HOST=localhost PEERJS_PORT=9000 PEERJS_PATH=/peerjs/filepizza/`, reusing servers already running on those ports.

### WebRTC Development

For full WebRTC testing with TURN/STUN:

```bash
pnpm dev:full
```

This starts Redis and COTURN containers for testing peer connections behind NAT.

## Key Dependencies

- `@tanstack/react-start` / `@tanstack/react-router` - Full-stack React framework and router
- `nitro` - Server build and runtime for the production output (dev dependency)
- `vite` - Build tool and dev server
- `tailwindcss` - CSS framework (via `@tailwindcss/vite`)
- `@tanstack/react-query` - Server state management
- `peerjs` - WebRTC abstraction
- `zod` - Schema validation
- `ioredis` - Redis client (optional storage)
- `vitest` - Testing framework
- `playwright` - E2E testing

Run `pnpm ci` before submitting PRs to ensure all checks pass.
